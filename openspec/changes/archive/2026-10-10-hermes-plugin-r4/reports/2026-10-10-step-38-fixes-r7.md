# Step 38 — M-R6-1: the visible mark is read with the Markdown consumer of the host

Date: 2026-10-10. Fix of the first publication blocker of
`tasks/revision-codex-hermes-cited-r6.md`, with its exact wording: interpret the visible syntax with the
semantics of the supported consumer, keep the map from the visible characters to the original spans to remove
the whole mark in dot, include the HTML breaks the consumer interprets, check the result with the independent
renderer, and return the existing fixed safe note when the sanitisation cannot complete.

## What changed

`hermes_cited/render.py`:

- `consumer_visible(text)` renders the document with `markdown_it` — the consumer the host uses — replaces
  every tag with a space, decodes every entity and collapses the whitespace. When the module is not
  importable the internal reader is the conservative fallback.
- `consumer_mark(text)` is the detection on that text; `contains_mark` delegates to it, so the cited path
  (`Line.has_mark`) and the gate predicates read the same authority.
- `_visible_tokens` now maps the visible characters back to the original spans and covers: an entity inside a
  link label, an inline link with a balanced target, a full, collapsed or shortcut reference resolved against
  the definitions of the document (which contribute nothing themselves), an image (a space, as its render
  shows) and an HTML inline tag (a space, so `<br>` is the line break the consumer renders).
- `strip_mark` checks its postcondition on that render, repeats the bounded removal and raises
  `SanitizationFailed` when it cannot complete, which the transformer turns into the fixed safe note.

`scripts/gate.py` adds the nine counterexamples to `gate_selftest()`, each as two predicates: the supported
consumer renders the mark of the draft and the render does not show it after the removal. The report titles
say round 7.
