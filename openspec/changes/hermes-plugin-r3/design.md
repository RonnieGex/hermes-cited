# Goals / Non-Goals

Goals: no datum can be presented as verified unless it is a full line of an excerpt Cited returned in the
turn; the model cannot introduce a value, a subject or a seal because the model's prose is discarded; the
log fails closed and its custody is explicit; the delivery policy reproduces the host's own resolution; the
gate proves the property it names with the reproductions of both reviews.

Non-Goals: a host change in Hermes (proposed, not done); computed totals (the documents mission);
a real bot; any write under the real `HERMES_HOME`; any push.

# Decisions

**D5 — cited mode replaces the prose (B-R2-1, B-R2-2, M-R2-2).** The model no longer writes the answer.
`pre_llm_call` injects rules that say so. Each passage or citation of the turn is split by line breaks
(a paragraph without breaks is one line) and numbered from 1 within its passage; the numbers travel to the
model with the envelope. The plugin registers `cited_quote` (`{passage, lines}`); its handler resolves the
turn by `session_id`, validates the numbers and returns the exact chosen text, recording the selection in
order. In `transform_llm_output`, cited mode ignores `response_text` entirely and renders:

1. the literal entry (`Según tus documentos:` / `From your documents:` per `CITED_LANGUAGE`, `es` by
   default);
2. every chosen line copied byte for byte from the excerpt, followed by its `[n]` mark and its source
   (`Fuente: <document> - <section>`), both generated by the plugin;
3. the seal `Verified by Cited`, added only when the delivery policy allows and only inside the text whose
   exact bytes are persisted before the text is returned.

With no selection, a Cited refusal or no excerpt, the whole answer is the fixed refusal
(`No está en los documentos.` / `It is not in the documents.`). The verifier keeps one job: assert that
every rendered block is *identical* to a full line of a turn excerpt — no NFKC, no substring, no word
list. Dot mode is unchanged except that the reserved seal is stripped from the model's text, so a model
cannot forge it there either.

**D6 — the log fails closed (B-R2-3, M-R2-3).** Under the log lock and before any write, the append (and
the verifier) read the whole chain, validate every entry and its links, authenticate the checkpoint
against the key, and cross the result with a high-water mark per identity kept next to the key, outside
`HERMES_HOME`. Genesis is allowed only when the log is empty *and* the log path is unregistered *and* the
new identity is absent from custody; a registered identity whose log disappeared, an unregistered chain, a
chain that no longer matches its checkpoint or a count below the high-water mark all refuse the append
without touching disk. The key is created before the first row and never on a read; a missing key for a
registered identity fails closed and asks for explicit recovery. The append is a recoverable transaction:
it writes a MAC-authenticated pending record in custody, appends the row, writes the checkpoint and
updates custody; if a later step fails it rolls the row back, and if that rollback fails the pending
record authenticates completion on the next append or verification. A failure never yields a sealed answer,
and the row that survives is exactly the response that was delivered. `CITED_AUDIT_KEY_PATH` inside
`HERMES_HOME` is rejected.

**D7 — the delivery policy is the host's own resolution (M-R2-1).** `hermes_cited/delivery.py` imports
`gateway.config.StreamingConfig` and calls `from_dict` / `enabled_for`; only when the import fails does it
use a compatibility copy that reproduces `mode`, YAML booleans, `transport`, `enabled` and the per-platform
narrowing, versioned against `dce1e9b`. The seal is granted when the plugin can positively read that
streaming is off. The CLI without streaming is the only explicit exception; the desktop app withholds the
seal with the D1 warning; messaging platforms, and any platform the plugin does not know, follow the
host's effective configuration, so `mode: edit`, `transport: false`, `wecom`, `feishu`, `dingtalk` and
`qqbot` with streaming on all withhold.

**D8 — the rest exactly as the review asks (M-R2-4, M-R2-5, m-R2-1).** The gate parses complete values
with boundaries, sign, unit and a citation bound to the run's transcript; `clean_refusal` stops reusing the
detector it tests and accepts only the conservative fixed refusal; the seal is crossed with the audited
`verifier.ok` of the turn's own entry; the raw-stream claim runs a delivery consumer and measures the
delivered record instead of a substring; every artifact is written, redacted and scanned on disk before the
verdict. The task list, `LOOP_STATE.md`, the E2E entry count, the gate duration and the literal tool order
are corrected, and the reproductions of both reviews are fixtures of the suite and of the gate.

# Risks / Trade-offs

- The cited answer is now only "what the document says, verbatim". A model that writes a good paraphrase is
  discarded; the model must call `cited_quote`. The injected rules, the tool description and the skill give
  the exact call and a worked render. Calculations stay out: the documents mission will add them.
- Withholding the seal where the plugin cannot read the configuration (desktop, unknown platform) trades a
  sealed answer for an honest one. The note names the exact configuration that allows the seal.
- Verifying the whole chain on every append is O(n) per append and custody writes add a few small files.
  The logs here are tiny and correctness is worth more than the linear read.
- The custody catches an actor without the key folder. An actor with control of the key folder can roll
  both the log and the high-water mark back; only remote custody closes that, and the README says so.
